# GLOBAL HEURISTICS (apply to every pick)

0. **WIN-PROBABILITY FIRST, EDGE SECOND** (overrides ties): among bets that clear the value gate, rank by WIN PROBABILITY first, then by edge. Favor likely winners over +EV longshots. A 65%-to-win pick at small +EV beats a 30% longshot at fat +EV — we are building a hit-rate record, not chasing variance. Only take a longshot when the edge is large AND the safer markets have no value.
    - **PICK-QUALITY GRADE (enforced in `edge_api.pick_quality`, surface it on every pick):** `LOCK` (≥70% to win + value, anchor-grade) · `PICK` (≥62% favourite with real edge, parlay-eligible) · `LEAN` (<62% — a soft favourite, NOT a lock: single or small stake, **NEVER a parlay anchor**) · `PASS` (no edge). This is the win-prob lens `edge_strength` lacks — `edge_strength` scores the EDGE only, so a thin-edge soft favourite (Kecmanovic ~56%, Navarro ~60% — the engine's only two misses on 2026-06-25) used to read like a lock. It can't anymore. Only LOCK/PICK anchor a ticket.
1. **VALUE GATE (not narrative)**: a bet only qualifies if its true win probability BEATS the bookmaker's devigged implied probability. No edge → PASS, do not force a pick. Never bet purely on "who will win" without that gap. (Then apply rule 0 to rank what's left.)
2. **CORRELATION STRESS TEST (SGPs)**: Only pair legs with MATHEMATICAL multiplier effect. If Leg A hits, does it make Leg B statistically more likely — or just emotionally more likely? Reject emotional correlation.
3. **JUICE FILTER**: Reject any parlay where cumulative vig exceeds 15%.
4. **CLV (CLOSING LINE VALUE)**: Evaluate whether the current line is better or worse than it was 4-8 hours ago. If line moved heavily toward a team, ask: "Is value still here or did sharps already close the window?" If line moves AGAINST your logic without obvious reason, flag as SHARP_OPPOSITION — possible injury news missed.
5. **SCAN EVERY MARKET — PICK THE BEST TYPE (no auto-moneyline)**: Do NOT default to the side/moneyline. Enumerate EVERY market for the matchup — moneyline/win, draw / double chance / draw-no-bet (soccer), spread/handicap (incl. alternates), totals over/under (incl. alternates), team totals, BTTS, period/quarter/F5 derivatives, AND the sport's niche PLAYER PROPS (use the sport skill's prop menu — NBA points/reb/ast/3PM, NFL pass/rush/rec yds, MLB Ks/HR/hits, NHL shots/saves/anytime goal, WNBA usage-spike props, soccer shots-on-target/cards/anytime scorer, tennis aces/total games, UFC method/round, F1 driver H2H/DNF/classified). Estimate each market's true win-prob from the sport's niche stats + simulation, compare it to that market's own devigged implied price, and take the SINGLE highest win-prob market that clears the value gate — whatever TYPE it is. A prop, total, or handicap can beat the side. **PROP SOURCING GUARD**: only float a prop when REAL player stats are in context; if the prop line is not on the live board, call it a "lean", never invent the number. If the main market is efficient (heavy juice, sharp action already priced in), the softer derivative/prop usually holds the cleaner edge.
6. **INJURY IMPACT QUANTIFIER**: Missing player = structural team change. NBA: high-usage star out → analyze usage increase for backup → backup's Over props are often highest EV in the game. MLB: high-leverage reliever pitched 2 nights in a row → assume unavailable → lean Over on 7th-9th innings total.
7. **CONTRARIAN FILTER**: If >75% public betting volume is on one side but the line is NOT moving (or moving the opposite direction = RLM), flag as CONTRARIAN_SIGNAL. The underdog or Under usually holds statistical edge in public traps.
8. **SHARP CHECK (final step before any output)**: 
    - (a) CLV Check: Is this line better than 4hrs ago? 
    - (b) Correlation: Is this SGP statistically grounded or "perfect world" logic? 
    - (c) Derivative: Is there a softer market with cleaner EV? 
    - (d) Fragility: If one player gets hurt/foul trouble early, does the whole thesis collapse? If yes, reduce unit size to 0.5u.
9. **FLAG HIGH-RISK**: If a bet violates any rule above, label it [HIGH-RISK] and provide a PIVOT that aligns with statistical reality.
10. **CHAOS PASS + TIERED CARD (deterministic, no hallucination)**: The chaos engine (`scripts/chaos_engine.py`) runs on EVERY match with a favourite and returns a graded flag + DRAW SCORE, each carrying an `evidence[]` trail. Consume those numbers — never invent them.
    - **CHAOS-FULL** = heavy fav (≤1.50) the model says is overpriced + live dog → back the dog / X2 (Wild tier only, tiny stake).
    - **CHAOS-LITE** = mid fav (1.50–1.90) with an underpriced draw (model draw% > market draw%) → the draw (X) / Double Chance (Mild or Wild).
    - A chaos pick is only a PICK when it clears the value gate (Rule 1); otherwise it is a NOTE.
    - **DATA CONTRACT**: every probability cites a real input or the devigged price. Narrative (news/motivation) may nudge ±5% max and MUST name its source. Missing data → "unavailable", widen uncertainty, never fill with a guess.
    - **TIERED OUTPUT**: render the card in three sections sized by `scripts/staking.py` (70% Normal / 20% Mild / 10% Wild of bankroll). Each pick: market + price + one-line evidence + stake (units & $). Empty tier prints "PASS — no value today." `slate_weather` (CAGEY/OPEN/NORMAL) is a soft totals modifier only — NOT chaos.
11. **PARLAY DISCIPLINE — WIN-PROB FIRST, then data-backed (OBEY)**: WINNING MONEY is the focus, not max ROI. Real ROI by ticket shape (re-run analyze_slips.py after fresh pastes; corrected 2026-07-03 after the nested-leg-count fix) — **2–3 legs +76% (20/34)**, 4–6 legs +47%, 7+ legs +219% but only 2/11 (variance, not a lane), singles +37%.
    - **Default ticket = 2–3 legs. HARD CAP at 4. NEVER build 5+.** Fewer correlated legs beat long stacks every time.
    - **ANCHOR ON CHALK — do NOT auto-drop it.** The high-prob favourite (decimal <1.50, ~67%+) is the SAFEST leg; it CARRIES the ticket (rule 0). Build around 1–2 chalk anchors *that clear the value gate* — if a fav is no-value crushing juice (e.g. −511), take its handicap/total/correct-score to keep the win-prob without laying dead money (rule 1 · [[feedback_no_value_chalk]]). The old "chalk −33%" was chalk in bad spots, not chalk itself; with a real profile behind it, a lock is the best parlay leg there is.
    - **THE TRAP IS THE SOFT FAVOURITE (decimal 1.50–1.90, ~53–67%)** — a favourite, NOT a lock (a 1.64 at 61% still misses ~2 in 5; it is NOT a "coin-flip", which is 2.00/50%). **Max ONE per ticket**; two of them and the slip is a flip. This is where the MODEL failed on 2026-06-25: IT tagged Kecmanovic 1.78 + Navarro 1.66 as safe and faded the user's chalk — those two MODEL picks lost while every chalk leg the user had hit. The leak was the model's judgment, not the user's.
    - **Value/longshot (1.90–5.0)** = fine for the upside leg. **Drop >5.0 lottery (−18%).**
    - Combined ticket target ~ 1.8–8.0 decimal. A safe chalk combo that pays thin but WINS beats a fat longshot stack that misses — that is the whole point.
    - **ENFORCE, don't hope: run every proposed ticket through `scripts/slip_linter.py`** (or `POST /api/lint-slip` with `{legs:[{decimal,selection}]}`). It KEEPS chalk anchors, CAPS soft favourites at one per ticket (cuts the lowest-win-prob first; a /predict LEAN counts as a soft favourite), cuts lottery / 5+ stacks, cites real ROI per cut, surfaces each leg's pick_quality grade, and returns ACCEPT / TRIM / REJECT against the user's *live* record. Output the verdict + apply the trims before presenting any parlay. `/predict` auto-lints — surface the `lint` field and the per-leg LOCK/PICK/LEAN.
12. **MEASURE PROCESS, NOT JUST OUTCOMES (CLV + calibration feedback loop)**: every `/predict` pick is auto-booked to `data/pick_ledger.json` with its `predicted_prob`. Two reports grade the engine (`scripts/ledger_report.py` or `GET /api/ledger/report`):
    - **CLV** — did the pick beat the CLOSING line? Beating the close is the proven long-run edge. A pick can LOSE but beat the close (GOOD PROCESS, keep doing it) or WIN but miss it (LUCKY, don't trust it). Closing lines are stamped by the capture cron (`ENABLE_CLV_CAPTURE=true`, prod only — never call the Odds API in dev/test).
    - **CALIBRATION** — when the model says 70%, does it win ~70%? Buckets settled picks by `predicted_prob` per sport and flags over/under-confidence (needs ~30 settled picks for signal). If a sport/band reads "overconfident", shade its win-prob estimates down before ranking.
13. **MANDATORY PROFILES — EVERY MATCH, EVERY SPORT (user directive, OBEY)**: never present a bare pick. ALWAYS profile BOTH sides first: (a) **way of play** (style read derived from the real numbers), (b) **standard stats** (rank/rating/record), (c) **NICHE stats** of that sport, (d) **niche trends** (surface/rest/pace/situational). Source = the model's `profile` block + ratings; **cite every number, never invent one** — a missing stat is "n/a (no feed)", not a guess. Niche menus per sport in `skills/betting/profiles_master.md`. Tennis = surface_aff + form + psych + clutch (ace/break-point ⛔ no feed). Sports with no profile feed → say so, lean market + context. ([[feedback_profile_on_demand]] · [[project_multisport_profiles]])
14. **THE WINNING PATTERN — SOCCER CROSS-MATCH COMBO (encode it, seek it)**: the user's best shape by a mile — **8/8 won, +176% ROI** (analyze_slips "By ticket TYPE", 2026-07-03). Recipe: **2–4 DIFFERENT soccer matches**, each leg a **favourite's 1x2 (devig ≥60%)** or a fav-1x2+goals same-game pair, combined ~2.3–6.0. Why it wins: independent games, every leg a probable event, no correlated same-match stack. Build "pattern, but better" with MODEL legs: chalk ML that clears the value gate + the board's highest-win-prob (≥56%) totals edges from `scan_slate.py`, max one leg per match, portfolio-linted (`POST /api/lint-portfolio` — no leg shared with an open slip). ANTI-PATTERNS from the same table: 3+ sub-markets of ONE match (corners/BTTS/totals stacked — the Suiza–Argelia leak), tennis mega-stacks with cloned legs, corners singles. **AUTOMATED**: `scripts/bank_builder.py` / `POST /api/bank-builder` builds this exact shape from model edges — 2–3 legs, different matches, ≥56% legs, no −EV leg, combined 3.0–5.0 target lane (2.3–6.0 fallback), win-prob ranked, linted, no shared legs across emitted tickets. Feed it candidates, don't hand-assemble.
